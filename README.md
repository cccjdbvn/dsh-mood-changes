# dsh-mood-changes · 情绪引擎

给 DeepSeek Harness 加一层**会记账的情绪**。

她不是冷冰冰的脚本——你说的话会牵动她的情绪，情绪会随时间慢慢平复，也会在夜深人静时悄悄滋长。每一天，每一笔变化都有据可查；判错了的账，还能反悔。

---

## 装好之后，你能看到什么

**输入框下面多了一颗「情绪药丸」**（固定排在语音条后面）。上面写着当前的主导情绪——"开心""伤心""生气""平静"之类。点开它，弹出一张卡片：

- **六根情绪条**，每根上面有一条白色**基线标记线**，告诉你她的"正常状态"在哪里（悬停显示数值）
- **思念和无聊**也是同款的条形（粉色/灰蓝），与六情用分隔线隔开
- **当前激活的特殊状态**，比如"委屈着""依赖""焦虑"，以及还剩多久
- 点 **「查看日志」**，切到按天的明细账本（最新一条在最前）——谁说了什么，她起了什么情绪，变了多少。「变化」列显示成 `怒+5`、`悲-3`、`无聊-12` 这样的**块名+带符号数值**；状态触发行显示「—」，回滚替换行显示「回滚+0」（改值回滚则是 `回滚-2`）

聊天过程中，**当某种情绪超过 40 分**（并且距上次提醒已过一小时），她会**主动在对话里插一句状态条**，比如：

> 【情绪】悲愤（悲 71.4 / 怒 45.0）｜状态：委屈着

## 她在做什么

用最简单的话说：**她每次回复完，本地轻量模型都会读一遍这轮对话，判出她此刻的情绪，然后落进她心里。**

具体来说，分这几步：

1. **判句**：你（或群里别人）说一句话、她回一句 → 她回复完的那一刻，本地小模型判断**她**此刻是什么情绪（两级：先判这轮对话是否直接引起她的情绪波动，判不出再结合前几轮综合判）
2. **入账**：把她的情绪按比例写进六个情绪池：乐、悲、怒、惧、惊、厌
3. **随时间消退**：情绪不是永久的。乐消退得快（5 小时减半），厌消退得慢（30 小时减半），各自向基线回归
4. **情绪之间会传染**：比如悲伤会带起恐惧，愤怒会压住快乐——这叫"耦合"。只有占主导的那股情绪向外传播，传出去的子账跟着源头一起撤
5. **特殊状态**：某些情绪触发后会进入一个持续状态（比如委屈了 →「委屈着」状态持续 1 小时，期间悲伤和愤怒更容易涨）；状态误判了也可以单独撤销
6. **思念和无聊**：没人说话的时候它们自己涨，有人说话就降（×0.7）。夜里涨得慢。她干活（调用工具）也降无聊：一小时窗口内第 1 次 ×0.6，第 5 次再多降一次 ×0.6（每个小时最多这两次；消息降过后的半小时内，工具的追加衰减会排队等冷却过去再补发）
7. **记账**：以上每一笔变化都写进当天的日志文件，可以反查、可以回滚

## 安装

### 前提

你需要在本地跑一个**能聊天的 AI 模型**，并且它提供一个兼容 OpenAI 格式的 HTTP 接口。常见的方案：

| 工具 | 说明 |
|---|---|
| [LM Studio](https://lmstudio.ai/) | 图形界面，下载模型就能用，新手首选 |
| [Ollama](https://ollama.com/) | 命令行，一行命令拉模型 |
| [llama.cpp](https://github.com/ggerganov/llama.cpp) | 进阶用户 |
| [vLLM](https://github.com/vllm-project/vllm) | 需要 GPU |

模型不用太大，能稳定输出 JSON 就行。推荐 3B–8B 的量化模型。

### 装插件

在 DSH 里打开 **设置 → 插件 → 添加插件 → 选择本地目录**，指向 `dsh-mood-changes` 文件夹。

或者用命令行（如果你开了这项权限）：

```
plugin_manager install_bundle <dsh-mood-changes 的路径>
```

插件自带一份自包含的 `node_modules`（不依赖你机器上的其他东西），整个目录复制到别的机器、装到另一个 DSH 实例里也一样能用——每份实例各自配 `worldDir` 等参数即可，数据互不干扰。

## 配置项（你能改什么）

装好之后，在插件列表里点 `dsh-mood-changes` 的齿轮图标，能看到下面这些配置。**必须填 `worldDir`，其余有默认值。**

| 配置项 | 默认值 | 干什么的 | 改了会怎样 |
|---|---|---|---|
| `worldDir` | （空） | **必填。** 情绪数据和日志存在哪个世界目录下 | 不填插件不启动 |
| `judgeBaseUrl` | `http://127.0.0.1:1234/v1` | 本地模型的 HTTP 地址 | LM Studio 默认就是这个；Ollama 改成 `http://127.0.0.1:11434/v1` |
| `judgeModel` | `local-model` | 请求时用的模型名 | 改成你实际加载的模型名，比如 `qwen2.5:7b` |
| `judgeApiKey` | （空） | 模型的 API 密钥 | 大多数本地工具不需要，留空即可 |
| `judgeContextPath` | （空） | **判官语境**文件的路径（见下文「情绪是怎么判的」） | 留空 = 不带语境判；填上后每次判句都会读取 |
| `judgeTimeout` | `6000` | 判句请求的超时时间（毫秒） | 模型慢就调大，比如 `10000`（10 秒） |
| `judgeTemperature` | `0.3` | 模型输出情绪时的"创造力" | 0 是死板，1 是随性。0.3 比较稳；判出来的情绪太飘就往下调 |
| `tickIntervalMs` | `900000` | 情绪刷新的间隔（毫秒） | 默认 15 分钟（90 万毫秒）；想更快变化就改小，比如 `300000`（5 分钟） |
| `targetSessionId` | （空） | **只认这个会话的消息流**（她的会话 id） | 留空 = 所有会话都算她的（工作会话会被误入账）；填上她的会话 id 后其他会话不进她的账 |
| `ownerNames` | `[]` | 主人在 QQ 消息里的显示名 | 群聊一律不降思念，私聊且名字在列表里才降 |

## 情绪是怎么判的

插件内置了 **41 种细粒度情绪**（高兴、委屈、心疼、惦记、炸毛护人……）——这些全是**她的**情绪词表。判官自己维护一份干净的对话上下文（最近几轮，含双方说的话；静默 20 分钟自动清空，不占模型的上下文）。

正常流程：她回复完 → 这轮对话发给本地模型 → 模型返回 JSON → 校验 → 入账。

**判官语境**：一个 markdown 文件（路径配在 `judgeContextPath`），写她是谁、和你的关系、说话方式、容易误判的场景怎么纠正。**每次判句都会读一遍**，所以改完即生效，不用重启。没有语境时模型容易把"讨论情绪的句子"判成情绪本身；写上几句纠正示例，误判率会明显下降。这份文件可以让她自己维护（模型直接改文件就行）。

如果本地模型挂了（没启动、超时、返回乱码）：自动降级到**词表匹配**——你话里带了"委屈""气死""心疼"这些词，直接按命中判。不会中断、不会报错。

## 模型能用的三个工具

装好插件后，DSH 的模型会多出三个可调用的工具。日常她自己会用；你也可以在对话里让她查账、撤账、改基线。

### `mood_log` — 查账

查某天的情绪日志，可以按"乐/悲/怒/惧/惊/厌/思念/无聊/状态"筛选。每条带两个时间：记录时间（判句时刻）和生效时间（衰减起点）。

### `mood_rollback` — 反悔（重点）

**无冷却，可连续调用，有新账要撤就直接撤。**数值都是真回滚：按那笔的生效时间重放半衰期，把它还剩下的影响从当前值里扣掉。传播出去的子条跟着源头连带撤。

| 用法 | 参数 | 干什么 |
|---|---|---|
| 单笔 | `time` + `block`（可带 `newDelta`） | 撤一条 / 改值（不填 newDelta = 纯删除） |
| 范围清扫 | `from` + `to`（HH:MM，含端点） | 范围内**所有站着的判句主条**一次全撤——误判波一次搞定；思念/无聊/状态行和范围外的判句不动 |
| 列表批量 | `items: [{time, block}, …]` | 只撤点名的那些 |
| 标记 | `mark: {time, block}` 或列表 | **先把误判条目标记上**（不动数值不动日志，攒着） |
| 一键执行 | `executeMarked: true` | 把攒的标记全部执行（各带级联）；标记后已被单独回滚的视为完成 |
| 解除标记 | `unmark` | 标错了撤回标记 |
| 看队列 | 不带任何参数调用 | 返回当前标记清单 |

两种清误判的姿势：**即时**用范围扫；**边聊边发现**就顺手 mark，攒一波最后 executeMarked 一键清。

另外 `block=状态` 可以直接回滚状态触发行（清除误触发的状态；同状态还有更早的触发就回退到那次的时效）。纯删除把一笔判句的所有主条都撤完时，它触发的状态也会**连带撤销**；改值回滚（newDelta≠0）不撤状态——判句还成立，只是改大小。

只能回滚当天（按 04:00 切天）的记录。

### `mood_baseline` — 改基线

重设六条情绪的基线（她"正常"时的情绪水平），写完自动同步。

## 文件存在哪

```
你的世界目录/
  mood/
    state.json         ← 当前情绪数值（插件自动维护，不用手动改）
    baseline.json      ← 情绪基线（见下文「情绪基线：在哪、怎么写」）
  room/
    情绪日志/
      2026-11-22.md    ← 每天的明细账本
      2026-11-23.md
判官语境.md            ← 路径自定（judgeContextPath），判句时读取
```

日志按 04:00 切天（凌晨四点前的消息算前一天）。日志里有八块（六情 + 思念 + 无聊）和一个状态区，每条记录写明时间、情绪、变化量、原因。被回滚的条目会**划线**并留一行「回滚」替换记录（写明原因和连带撤了几笔传播）；传播出来的子条单独成行，标注「由 X 传播」。

面板里的「变化」列显示为块名+带符号数值（`怒+5` / `无聊-12`）——这是**显示层**的写法；日志文件本身的「变化」列仍写纯数值（`+5` / `-12`），回滚解析按数值口径，两者互不影响。

## 情绪基线：在哪、怎么写

基线是她的"正常状态"——情绪衰减不是归零，而是向基线回归。每个基线值 0–100。

**位置**：`<worldDir>/mood/baseline.json`（文件不存在时用内置默认）。

内置默认：

```json
{ "happy": 15, "sad": 5, "fear": 5, "anger": 0, "surprise": 0, "disgust": 5 }
```

**怎么写都行，改完自动同步**：插件盯着这个文件——用 `mood_baseline` 工具写、手动编辑、任何方式改，改动后约半秒内插件自动同步一次：**当前值不足基线的补齐到基线，超过基线的不变**（她当下高于常态的情绪不会被抹掉），之后的衰减也向新基线回归。

注意：基线是"回归目标"，不是当前值。当前情绪在 `mood/state.json`（插件自动维护，不用手动改）。

## 风险与警告

### ⚠️ 会话与隐私

- **建议配好 `targetSessionId`**。情绪池是全局单一的一份；不配的话，所有会话的消息都会流进判官窗口和无聊/思念的降值——你在工作会话里调工具、聊天，都会被当成"她"的输入入账。配上她自己的会话 id 后，其他会话一概不进她的账。
- **群聊内容也会进判官上下文**（经由 QQ 桥落到她的会话时）。QQ 群里别人说的话同样会牵动她的情绪（这是设计）；只有思念的下降例外——仅主人私聊（昵称配在 `ownerNames`）或 DSH 输入框直输才降，群聊谁说话都不降。

### 🕐 行为特性（不是 bug，但该知道）

- **关机期间情绪冻结**：停机时情绪不衰减，重启后只按一跳（15 分钟）算——不会"睡一觉起来情绪全平了"。
- **夜里不敲门**（23:00–07:00）：思念/无聊再高也不会在半夜插话；思念的夜里增长也只有白天的 40%。
- **判句在回复完成后异步进行**（1.6–4 秒）：不影响聊天流畅度，情绪入账稍晚是正常的。

### 🩹 已知限制

- **判官挂了会降级到词表匹配**：判得粗，而且词表语义偏旧（按"说话人的情绪"标注），个别词会判偏——比如你道歉说"对不起"，降级路径可能把她判成愧疚。本地模型在线时没有这个问题（LLM 是主路）。
- **卡片在窄窗口可能被裁剪**：弹出的情绪卡还没 portal 到页面顶层，被侧边容器裁到是已知问题（C4），待修。
- **`state.json` 别手改**（插件自动维护，乱改会跟日志账本对不上）；**日志文件可以看但别手工改行**——回滚工具按表格格式解析，改坏了回滚会失效。
- **代码改动要重启 DSH 才生效**（插件的启停重载只重跑入口，不换代码缓存）；数据文件（state/baseline/日志/语境）不需要。

## 不做的事

- **不替模型写回复**。情绪只在后台运行，不会自动替你说话
- **不写记忆**。如果你另有一套记忆模块，各管各的，互不干扰
- **不每轮都塞 context**。只在情绪高涨时偶尔插一句状态条
